# EScope 桌面管理工作台设计

版本：0.5，2026-10-09。性质：产品扩展设计，不是功能已经实现的声明。

本规范依据用户最新需求扩展产品范围，优先于旧方案中的“只读查询工具”定位。
只读保留为默认安全模式，而不是产品能力上限。现有 HTML 仍只是查询与设置样式原型。

## 1. 产品定位与覆盖边界

EScope 是跨 Windows、macOS、Linux 的 Elasticsearch 查询、诊断与管理客户端。
目标覆盖 ES 常用数据面和管理面的大部分工作流，而不是为所有 API 都手写一个表单。

三层覆盖：

1. 核心可视化：连接、查询、健康、节点、分片、索引、文档、别名、模板、快照、任务。
2. 进阶工作流：生命周期、数据流、采集管道、安全、跨集群、向量检索、迁移。
3. 受控 REST：版本匹配的补全、文档、请求校验与授权，覆盖没有专用界面的 API。

“支持大部分”通过可测试的 API/工作流清单衡量，不使用没有分母的百分比。
每项标记：专用 UI / REST 可用 / 只读 / 待实现 / 不适用 / 无权限 / 需许可证。
核心工作流不能仅因 REST 可调用就宣称具备完整可视化支持。

ES 不等于整个 Elastic Stack：Kibana 仪表盘、Fleet UI、Logstash 部署管理、Elastic Cloud 控制面
需要各自的接口、凭证与适配，不能通过 ES 地址自动获得，也不纳入第一批完整支持承诺。

### 1.2 地图与关系的新增产品边界

- 地图/关系分析复用查询工作台及稳定连接上下文，作为明确打开的分析视图，
  不替换默认索引入口，不增加第二套管理首页。管理配置仍归设置右侧。
- 每次分析绑定连接、索引/Data View、查询、时间和字段的不可变快照。
  布局、缩放、主题、语言、节点拖动不隐式执行查询或改写 DSL；查询范围变化须明确执行。
- 地图分别处理 `geo_point`、`geo_shape`、缺失和无效坐标；显示坐标系、采样/桶范围、
  截断与部分失败。热力/聚类结果不冒充全量明细，地图关联不能默认拉取全部文档。
- 外部底图/瓦片默认不请求，先告知外部网络与地理范围泄露风险，再由用户配置并明确启用。
  离线/无底图时仍能查看已有几何数据；不能绕过受限 IPC 增设通用 URL/认证头代理。
- GeoJSON/shapefile 导入是独立的真实写入流程，先解析与预览，检查坐标系、编码、文件配套、
  解压大小/路径和 Mapping，再进入 W01/W03；逐项失败可定位，不能把部分导入报完整成功。
- Graph 首先面向 Elasticsearch Graph API：种子/字段、相关性、采样、扩展深度、数量上限、
  节点/边筛选与证据回查。接口缺失、无权限和许可不足分别显示，不静默换成语义不同的算法。
- Graph 的共现/相关性不是因果或显式业务关系；样本中没有边不证明数据中不存在关联。
  保存默认只包含查询/字段/布局定义，不额外持久化文档或节点敏感值。
- 图表、地图、图布局与空间解析优先评估成熟库，在各自子项中验证许可证、离线能力和数据规模
  后才引入依赖；本次不决定新的运行时、安装库或启动服务。

## 4. 连接中心

### 4.1 连接方式

| 场景 | 配置 | 注意事项 |
| --- | --- | --- |
| 本地/内网、自建 ES | HTTP/HTTPS、单地址或节点地址列表 | 默认 HTTPS；明文认证提示风险 |
| 负载均衡/反向代理 | 基础路径、自定义请求头、超时 | 保留路径前缀，禁止凭证跨主机重定向 |
| Elastic Cloud Hosted | ES endpoint 或 Cloud ID 解析 | Cloud ID 不是凭证，控制面与 ES 访问分离 |
| Elastic Serverless | 服务 endpoint、支持的认证 | 隐藏节点/分片等不开放的运维能力 |
| 企业网络 | HTTP CONNECT / SOCKS5 代理、企业 CA | 代理凭证单独存储，代理与 ES 认证分离 |
| 堡垒机 | SSH 隧道、密钥/agent、known_hosts | 校验主机指纹，不自动接受变化 |
| 双向 TLS | CA、客户端证书、私钥或 keystore | 验证客户端认证与 ES 身份映射，保留正确 SNI |
| 托管 ES 服务 | endpoint、服务要求的认证 | 不把所有云厂商当成同一种协议 |
| OpenSearch / AWS 托管 | 独立驱动与 SigV4 适配路线 | 不承诺与 Elasticsearch 兼容；STS 到期刷新 |

认证覆盖无认证、Basic、API Key、Bearer token、客户端证书。
SSO/OIDC/SAML 需专用交互登录与令牌生命周期适配，不能把浏览器 Cookie 复制当通用解决方案。
上述为覆盖目标，实施阶段见路线图；不是当前预览已支持。

### 4.2 连接向导与诊断

步骤：类型与地址 → 认证/TLS/代理 → 连通与身份 → 能力和权限 → 保存。
分别显示 DNS、TCP、TLS、HTTP、认证、集群识别、元数据权限和查询权限的结果与耗时。
集群健康 red 不等于连接失败；无 monitor 权限不等于不能搜索已授权索引。

保存连接 UUID、环境、标签、默认访问模式、凭证引用、能力快照与最后成功时间。
工作区保存上次选择的连接配置 ID；它与服务端 cluster UUID 不是同一个字段。
启动优先恢复有效选择，无有效记录默认持久化列表第一项，单连接隐藏选择器。
多连接在首页右上角和设置的连接中心切换，连接名称可编辑，重命名不影响身份与选择。
删除当前配置后回退剩余第一项，零连接进入添加空状态；原型零配置时的演示连接只用于评审。
切换连接隔离查询与监控上下文，不把旧结果重新标为新连接，也不自动执行原查询。
节点嗅探默认关闭，避免云端/代理/隧道发现不可达内网地址。
多节点需验证集群身份，不能把不同集群误当故障转移节点。
只有明确可重试的读取请求自动重试；非幂等写入超时显示“结果未知”，先核实再决定重试。
连接测试不执行写入，不运行宽范围健康报告或全量数据扫描。

## 5. 集群概览与健康诊断

### 5.1 概览页

顶部是连接与状态摘要，下一行为紧凑指标带，主体为趋势与问题列表，不堆大量浮动卡片。

- 身份：名称、UUID、ES/Lucene 版本、部署类型、许可证状态、当前用户。
- 分配状态：green/yellow/red、主分片/副本、未分配、初始化、迁移数量。
- 容量：索引/数据流、主分片存储与总存储、磁盘余量。
- 负载：搜索与写入速率、JVM 堆、GC、线程池拒绝、任务积压。
- 异常：按影响与证据排列，点击进入对应节点、索引或分片。

文档计数标明来源：Lucene 文档计数可能包含 nested 隐藏文档，不冒充用户文档精确数量。
未知、无权限、数据过期、请求失败均独立显示，不能填 0 或显示健康。

### 5.2 健康语义

green 表示主副分片均已分配；yellow 表示主分片已分配但部分副本未分配；
red 表示部分主分片未分配。分配健康不代表低延迟、无错误或业务正常。

健康检查分三层：

1. 连通与身份：是否访问到目标集群，凭证是否有效。
2. 分配健康：cluster health、分片恢复、allocation explain。
3. 运行风险：磁盘水位、堆/GC、拒绝、积压、读写块、快照失败或长时间未成功。

支持的版本使用 health report 辅助诊断，旧版本降级到明确规则。
检查默认只读，“解释原因”与“修复”分开；AI 不自动修改副本数或分配设置。
每项显示严重度、首次/最近观测、受影响对象、证据字段、可能原因、建议和对应 API。
建议不是事实，缺少监控历史不能断言“持续高负载”。

例：磁盘触达水位 → 查看节点磁盘与分配解释 → 查受阻索引 → 审核容量/迁移方案。
不能简单提供“一键移除只读块”来掩盖磁盘仍满的问题。

## 6. 监控与告警

### 6.1 数据来源与采样

使用 JSON 结构化 API 作为应用数据源，不依赖解析 CAT 文本。CAT 在 REST 中保留人工诊断用途。

| 数据 | API 家族 | 策略 |
| --- | --- | --- |
| 分配健康 | cluster health | 轻量周期采样 |
| 节点角色/版本/配置 | nodes info | 低频缓存 |
| JVM、FS、OS、线程池、breaker | nodes stats | 指定所需 metric，避免全量 |
| 搜索/写入/缓存 | index/node stats | 按目标聚合，明确统计口径 |
| 分片恢复 | recovery、受限 cluster state | 页面可见且按索引范围读取 |
| 热线程 | nodes hot_threads | 用户手动触发，非高频后台采集 |
| 集群排队 | pending tasks | 与执行任务列表分开 |
| 执行任务 | tasks | 分组、按目标与任务类型筛选 |

初始默认建议：活动监控页 15 秒、健康摘要 30 秒、静态元信息 5 分钟，可按连接调整。
这些是采样默认提案，不是吞吐保证；大集群需要压测后调整。
单连接共享采样器、限制并发、无重叠请求、带抖动退避，429/超时不继续加压。
后台标签降频；暂停、休眠、断网以断点显示，恢复不补造历史数据。

速率由相邻有效计数器差值 / 实际采样间隔计算；节点重启、计数回退或对象变化时重建基线。
累计 query_time/query_total 的差值只能作为相关统计口径的平均耗时，不能称为端到端 p95。
主机内存、进程内存、JVM 堆分开；共享主机的 OS 指标不能重复相加成集群容量。

### 6.2 历史与通知

默认内存保留本次会话窗口；用户可开启有配额与保留期的 SQLite 聚合样本存储。
不保存文档原文；指标中的节点名、地址等仍属于敏感元信息，按策略保护。
长时间历史优先接入已有监控系统，需单独选择来源并解释查询权限。

本地规则支持阈值、持续时间、连续命中、恢复阈值、冷却、去重和维护静默。
只在实际观测后标记触发/恢复；数据缺失作为独立告警，不当成恢复。
桌面通知先申请权限。桌面应用关闭或电脑休眠后不会继续可靠监控。
7×24 小时采集告警需独立常驻服务或现有告警平台，不能靠桌面定时器承诺。
本轮仅设计该能力，不创建任何真实自动监控任务。

## 7. 节点与分片

### 节点页面

可排序筛选的列表：节点名、角色、版本、当前 master、CPU、load、heap、磁盘、GC、拒绝量。
角色用图标加文字/tooltip，不要求用户记缩写；缺少指标显示原因。
详情页标签：概览、性能、线程池、缓存/breaker、设置、插件、热线程、驻留分片。
指标支持统一时间游标；节点消失时保留历史样本身份，不能与同名新节点混合。

### 分片页面

提供列表与矩阵两个视图：节点为行、索引为列，大集群双向虚拟化。
主副本、编号、状态同时用文字和形状表达；未分配单独一行。
筛选索引、节点、主/副本、状态；点击显示大小、原因、恢复阶段和 allocation deciders。
诊断链：未分配 → allocation explain → 节点候选与拒绝原因 → 可审核建议。

reroute/重试分配使用专用操作表单，先 dry_run + explain，再显示目标与预期影响。
dry_run 不是安全保证，执行前重新核验目标；绝不通过拖动即刻移动生产分片。
禁止把分配开关做成无确认的普通 toggle。
强制分配 stale/empty primary 涉及数据丢失，默认禁用，高风险流程单独隔离。

## 8. 索引、文档与搜索管理

| 页面 | 核心功能 | 编辑规则 |
| --- | --- | --- |
| 索引列表 | 健康、open/closed、别名、主副本、文档、存储、创建时间、生命周期 | 批量选择按权限和操作兼容性分组 |
| 索引详情 | 概览、文档、Mapping、Settings、统计、分片、别名、生命周期 | JSON/表单双视图，保存前 diff |
| 新建索引 | 名称、模板匹配、Mapping、分片/副本、分析器 | 模板模拟，明确不可轻易更改字段 |
| 别名 | 目标索引、filter、routing、write index | 单次原子 aliases 请求，不分步留下空窗 |
| 模板 | composable/component 模板、优先级、匹配模式、模拟 | 区分 legacy 模板，不混用更新协议 |
| 文档管理 | 创建、编辑、删除、批量、JSONL/CSV 导入 | 乐观并发控制，冲突展示版本差异 |
| Mapping | 类型、searchable/aggregatable、nested、多字段、runtime fields | 不承诺原地改已有字段类型，提供 reindex 路径 |
| 分析器 | 文本输入、analyze、token/position/offset 查看 | 与真实索引分析器配置绑定 |
| 搜索增强 | 聚合、profile、explain、highlight、suggest、向量/hybrid | API/字段类型受版本与许可证限制 |

文档更新使用 seq_no/primary_term 等相应并发机制，不盲目覆盖别人修改。
bulk 逐项显示成功失败；HTTP 200 不能代表所有写入成功；重试仅针对可安全重试项。
update/delete by query 先展示查询与影响范围，异步任务进度、版本冲突和部分完成单独呈现。
refresh、flush、force merge、clear cache、close、delete 都是明确命令，附成本/影响提示。
force merge 不能作为“性能一键优化”；索引删除默认排除系统/隐藏资源和宽泛通配符。

查询保留原有可视化/DSL 能力，增加按能力显示的 ES|QL、SQL、EQL。
不同语言是独立草稿与结果契约，不承诺任意互相转换。
SQL 游标、ES|QL 行数限制、EQL 异步结果与 DSL PIT 分页分开管理。
向量输入来源需明确：用户提供向量或经授权调用 embedding，不把聊天模型当 embedding 模型使用。

## 9. 生命周期、数据加工和备份

| 模块 | 专用工作流 | 风险/边界 |
| --- | --- | --- |
| 数据流 | backing indices、write index、rollover、模板 | 数据流生命周期与 ILM 按部署类型区分 |
| ILM | 策略、阶段、索引 explain、错误重试、策略 diff | 不通过手动推进阶段跳过危险条件 |
| Ingest pipeline | processor 列表、JSON、simulate、逐步结果 | 先样本模拟，写入前说明影响 |
| Enrich / 同义词 | 策略与集合、验证、构建任务 | 受版本能力控制 |
| Reindex | 源/目标、Mapping、pipeline、限速、任务、冲突 | 不是事务，不保证自动回滚；切换别名前验证数据 |
| Transform | 创建配置、预览、启动/停止、统计 | 权限与集群支持决定可用性 |
| 快照仓库 | 仓库注册、验证、类型配置、可达性 | 仓库路径是服务端路径，不是客户端文件夹 |
| 快照 | 创建、列表、详情、状态、失败分片 | 快照完成需确认最终状态 |
| 恢复 | 索引选择、重命名、覆盖冲突、全局状态、feature states | 默认新名称恢复，系统状态高风险独立确认 |
| SLM | 策略、计划、保留、最近运行与失败 | 服务端计划与桌面本地通知严格区分 |
| 跨集群 | remote info、CCS 查询、CCR 状态 | 认证、版本、许可证与部署边界逐项验证 |

恢复不是通用撤销机制；升级、跨版本快照兼容与目标容量都需预检查。
仓库云存储凭证通常应在服务端安全配置，客户端不凭空替服务器安装插件或改 keystore。

## 10. 安全管理与 REST

安全页面包括当前身份、权限检查、用户/角色、API Key、到期时间与作用域。
权限不足时保留只读诊断入口，显示需要的具体权限；不要强迫用户提供超级管理员凭证。
新建 Key 只展示一次并提醒保存，列表不存储或回显密钥；角色 diff 标出权限扩大。
不默认允许修改内置/保留身份或系统索引。

REST 编辑器支持多请求、变量、补全、格式化、独立执行、响应查看、历史和导出。
每个请求展示实际 method、path、目标连接和风险级别，执行当前请求与执行全部分开。
混合读写批次先逐项解析；响应逐项记录，不把部分失败当整批成功。
不按 GET/POST 简单判断读写，使用 API registry 的语义与路径解析。
未知插件 API 默认禁止执行，需用户为可信连接显式登记；未知请求不能绕过只读策略。
路径规范化、防止跨主机绝对 URL、头注入和认证覆盖；变量展开后重新做风险校验。
历史、curl 复制和日志脱敏，不把认证头放入 AI 上下文。

## 11. 多模型接入与手动选择

### 11.1 分离提供方、模型与用途

ProviderProfile 保存协议类型、显示名称、base URL、认证引用、代理、超时和数据策略。
ModelProfile 保存 provider ID、真实 model ID/部署名、显示名称、能力、上下文限制与参数。
UsagePolicy 定义默认用途模型：查询生成、结果解释、运维诊断；embedding 单独配置。
同一个提供方允许配置多个 endpoint、账号与模型，不能只保存一个全局字符串。

### 11.2 接入矩阵

| 协议适配 | 覆盖方向 | 需要独立处理 |
| --- | --- | --- |
| OpenAI-compatible | 兼容服务、自建网关、部分国内服务 | 支持哪些路径和参数以实测为准 |
| OpenAI 原生 API | 原生 Responses / Chat 类接入 | 两种协议不能仅替换模型名混用 |
| Anthropic | Claude 服务 | 消息、system、工具与流式事件格式 |
| Google Gemini | Google 模型服务 | 内容块、工具、认证与流式转换 |
| Azure 托管模型 | 部署名、资源 endpoint、版本/身份 | model ID 与 deployment 区分 |
| Ollama | 本地模型服务 | 模型列表、原生协议、加载/超时行为 |
| LM Studio / vLLM | 本地或私有兼容服务 | 使用兼容适配并验证工具/结构化输出能力 |
| Bedrock / 企业网关 | IAM/签名、区域、模型标识 | 原生协议、临时凭证与治理限制 |

这些是计划的适配目标，不代表逐个提供方已经完成协议审计。
优先实现兼容协议、Ollama，再接原生与企业协议；新增提供方通过适配器而不是 UI 分叉。
用户可手填 model ID，模型列表拉取仅为可选便利；无法列出不等于无法调用。
没有凭证时不伪造“可用模型”；发现模型也不等于有调用权限，需要显式测试。
测试说明会发送的内容、目标与可能费用，不默认上传 ES 数据。

### 11.3 设置页面与会话选择器

设置 > AI 模型：

1. 提供方列表：名称、协议、地址、连接状态、最后测试时间。
2. 提供方详情：认证、代理、模型列表、手动添加、连接测试。
3. 模型详情：真实 ID、别名、文本/工具/JSON/embedding 能力、参数与限制。
4. 用途默认值：查询、解释、诊断；未配置则由用户选择，不强迫自动推荐。

AI 面板输入区旁显示“提供方 / 模型”的紧凑选择器，与外观设置不同，它是本次调用上下文。
列表支持搜索、最近使用、收藏、本地标识、能力及不可用原因。
每条响应记录实际模型、提供方、时间、上下文范围；用户可“换模型重试”生成并列候选。
选择优先级：本次会话显式选择 > 用途默认 > 全局默认。
调用进行中锁定本次快照；切换影响下一次，不悄悄替换正在流式输出的模型。
失败不自动转发给别的提供方；用户确认后重试，重新核对数据发送策略与费用。
重新发送对话历史属于新的数据传输，跨提供方切换时展示范围并再次确认。

参数按模型能力显示，不支持 temperature、reasoning 或结构化输出时禁用并解释。
上下文不足先展示裁剪计划，不静默删除影响查询正确性的字段和约束。
token/费用仅在提供方返回或有明确价格配置时显示；未知不写成零费用。

### 11.4 AI 运维助手

支持解释分配异常、JVM/磁盘指标、索引设置差异、提出 pipeline/ILM/查询候选。
只读上下文需授权且标记采集时间；模型输出不冒充实时集群状态。
建议包含证据、影响对象、风险、前置检查和待执行请求。
任何写入进入同一操作审核流程，模型不持有独立可绕过策略的执行入口。
聊天模型与 Elasticsearch Inference/ML 模型管理是不同模块、不同凭证和权限体系。

## 12. 权限、风险与审计

每个连接有三种客户端模式：

- 只读：查询、查看元数据与有权限的监控。
- 数据编辑：额外开放显式文档写入和导入。
- 运维管理：额外开放索引、集群、安全与备份管理。

模式只是客户端防误操作，真正权限由 ES 决定；升级模式不意味着获得服务器授权。
切换模式不自动执行已排队操作，生产模式可限定本次会话。

操作审核统一包含目标集群 UUID、环境、资源清单、方法、最终请求、diff、风险与提交时间。
确认凭据绑定规范化后的请求摘要和当前连接；任何参数或目标变化使确认失效。
不能只在前端显示弹窗，而让后端 invoke 无条件接受写入。
删除、权限扩大、恢复覆盖、分片强制分配需强化确认；高风险操作不能使用“以后不再提醒”。

任务中心记录发起、服务端接受、运行、部分完成、成功、失败、取消请求、结果未知。
取消只表示请求中止或任务取消请求已发出，必须核实服务端最终状态。
本地操作记录脱敏并有保留期限，不声称可替代服务端防篡改审计。

## 13. 架构升级

保留 React + TypeScript + Tailwind + Tauri/Rust，增加以下服务：

| 组件 | 职责 |
| --- | --- |
| Connection Driver | HTTP/TLS/代理/隧道/签名、身份与连接池 |
| Capability Registry | 版本、部署类型、许可证、权限、API 状态 |
| Operation Registry | 命令 ID、端点、风险、权限、校验、确认要求 |
| Query Engine | 可视化编译、语言适配、分页、结果契约 |
| Metrics Collector | 采样、差值、断点、配额、本地指标缓存 |
| Diagnostics Engine | 规则、证据、影响对象与建议，不自动修复 |
| Job Manager | 导入导出、reindex、快照、恢复、取消与状态追踪 |
| Model Gateway | 提供方适配、模型选择、流式、数据授权、费用信息 |
| Preferences / Audit | 外观、语言、快捷键、本地记录与数据清理 |

所有命令面板、按钮、REST、AI 候选走统一 Operation Registry 与后端授权校验。
异步响应绑定连接 UUID、页面上下文和请求版本，避免切换集群后旧监控数据污染新页面。
不要高频拉完整 cluster state；大数据源按范围、metric 和字段筛选。
集群 capability 缓存有 TTL，403、版本变化与重新认证后按需更新，区分不可用与未知。

## 14. 分期交付与覆盖标准

| 阶段 | 交付 |
| --- | --- |
| A 连接与观测基础 | 常见 HTTPS/Basic/API Key/CA、集群概览、健康、节点、分片、索引只读与结构化监控 |
| B 查询与多模型 | 完整查询闭环、基础聚合、兼容/Ollama 接入、手动模型选择、审阅与解释 |
| C 数据和运维管理 | 文档写入、批量任务、模板/别名、pipeline、生命周期、快照/恢复、安全、受控 REST |
| D 企业与进阶 | SSH/高级代理/mTLS/云签名、原生模型协议、跨集群、Transform/Inference/ML 等能力 |

A/B 是阶段成果，不将它们宣传为“大部分 ES 功能已完成”。
核心管理版至少需要 A/B/C 的明确支持清单与目标版本回归通过。
D 中复杂能力可以先用受控 REST 暴露，但必须在覆盖表里标注“无专用 UI”。
Rollup 等弃用/移除能力只对实际支持版本提供只读或迁移入口，不作为新功能重点投入。
ML、Watcher、Graph、Connector 等进阶族逐项评估版本/许可证/部署，不承诺全量首发。

验收工作流：

1. 无 monitor 权限仍可查询授权索引，健康显示无权限而非 red。
2. yellow 单节点副本解释正确，不误判主分片丢失。
3. red → 分片诊断 → dry_run → 人工审核形成完整链路。
4. 节点重启后速率不为负，断网曲线有断点，采集不无限重试。
5. bulk 部分失败可定位条目，写入超时不盲目重复提交。
6. 快照恢复默认隔离目标名，确认不随主题/语言切换丢失或误触发。
7. 用户可手填模型、手动切换与重试；跨提供方不能静默泄露历史。
8. REST、AI 与快捷键均不能绕过只读模式和目标资源确认。
9. 三系统、两语言、日夜/强调色、字体缩放、快捷键、屏幕阅读器分别验收。

下一版高保真原型应新增连接向导、集群概览、健康详情、节点详情、分片矩阵、
索引管理与 AI 模型设置/选择器，而不是继续只调整查询页的颜色。
