## 每批流程

1. 只读 AGENTS 最新摘要、计划当前段与相关验收，核对 Git 状态；不重新盘点整个产品或重跑旧底座。
2. 选有边界的一批相邻子项，简短说明影响范围后编码。大型任务可用 OMP 独占文件并行，
   简单任务主代理直接完成；共享合同单一所有者，所有写入同一 checkout 的会话不能重叠。
3. 做最小充分验证：受影响测试、对应 lint/typecheck；Rust 对应模块/fmt；UI 按需构建。
   高风险安全、IPC、schema 和写入流程不能省掉必要失败/取消/隔离用例。
   全量回归在高风险批次或阶段收口执行，原型未改不跑，不延长测试阈值掩盖错误。
4. 更新 AGENTS、plan、backlog 的简短状态，QA/人工事项按实记录；检查 diff 并提交本批相关变更。
   使用 main 与现有 Git 身份，不 amend 无关提交，不推送，不提交 `.claude/`、`.vscode/` 或秘密。
5. 待全部委派/命令退出，确认提交后，用 `list_projects` 定位 EScope，再以
   `create_thread` 的 project/local 新建恰好一个后继，不创建 worktree。
   提示只给当前 HEAD、下一批范围、关键约束、文档入口和本连续授权，不复制整段历史。
6. 以一次紧凑 `wait_threads` 确认后继已开始，输出创建会话引用后退出当前开发。
   当前会话此后不得继续写仓库；后继重复上述流程，不等待用户逐项确认。

新会话标题统一以“EScope 接续”开头，便于辨认，不为每个内部小项创建一个会话。
后继必须继承用户的每批提交、继续开新会话和最终睡眠条件。
若应用工具创建失败，保留提交并如实报告/有限重试；不伪造已开始，也不绕过授权创建外部代理。

## 接续监控

应用中的“EScope 连续开发接续”低频 heartbeat 仅作中断补接，不承担并行代码写入。
优先检查其记录的当前开发会话；运行中、等待审批/输入或已有活跃后继时不重复创建。
已完成且没有后继时，只在明确有可执行剩余项的情况下创建一个 local 后继。
每次正常交接如能访问该监控，应保留既有频率/通知配置，更新其当前会话 ID，避免扫描整条历史。
没有变化或没有可执行动作时保持安静，仅在中断、失败、需要用户操作或最终完成时通知。
本地接续依赖应用和本机执行环境可用；监控不构成远端常驻服务或完成保证。

## 真正结束与睡眠

- 自动化通过、待人工验收、外部阻塞和全部完成分开记录。
  未授权真实 ES/密钥库、生产写操作、许可证、签名/跨平台环境不能被当作已验证。
- 若只剩必须由用户提供授权/环境/人工结果的事项，汇总具体阻塞和补验入口，
  不创建无意义的新会话，也不宣称“全部结束”或触发睡眠。
- 所有范围内任务及其必需验收真正完成后，执行最终风险相称回归、提交所有相关成果、
  写最终交接，确认相关开发/测试/委派已经退出，并停用接续监控。
- 然后按用户授权调用系统的正常睡眠功能；不关机、不重启、不强制结束程序，
  不更改休眠/唤醒或其他电源设置来绕过失败。睡眠不可用时如实记录，不声称已睡眠。
