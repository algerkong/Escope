## 2. 不再反复讨论的设计基线

产品范围以 [平台设计](platform-design.md) 为准，设置交互以 [设置规范](settings-and-shortcuts.md) 最新决策为准，
视觉以 [视觉系统](competitive-and-visual-design.md) 为准；[产品设计](product-design.md) 保留查询语义、安全和结果契约，
不采用其早期只读产品上限。

1. 默认首页是查询工作台的索引打开入口；首次明确打开目标新增独立索引标签并只读预览，再次打开只定位，
   不覆盖其他索引或查询草稿/结果。AI 初始默认收起，用户的下次启动偏好可以覆盖。
2. 连接、模型、集群、节点、分片和索引复用设置右侧区域，左侧设置导航固定保留。
3. 关闭设置回到原查询，保留条件、草稿、结果、视图与滚动状态。
4. 连接使用不可变 ID；名称可改、顺序稳定，启动恢复上次有效 ID，否则选第一项。
5. 零连接显示添加空状态，单连接隐藏选择器，多连接时顶部与设置选择同步。
6. 切换连接或标签不自动查询；标签固定绑定原连接，激活标签同步有效连接上下文；
   异步响应和迟到的选择写入不得污染新意图。
7. 日夜、四种强调色、中英文、字体和密度从底座阶段纳入，不在最后补国际化。
8. 只读是默认访问模式而非能力上限；写入能力必须等待后端授权与审核流程。
9. 正式运行无默认演示连接；fixture 仅用于测试或显式开发模式，不能在真实请求失败时替补数据。

## 3. 工程结构与迁移方式

React + TypeScript + Vite + Tailwind 4 + Tauri 2/Rust，可访问基础控件与 Lucide，国际化用 i18next/react-i18next，
依赖版本以锁文件为准。已引入 TanStack Table + dnd-kit（本地排序、列宽与顺序，有界分页）、本地延迟加载的 Monaco（Q03）、
TanStack Virtual（已加载列窗口化）；图表首批选用 Visx 纯 SVG（Q06，设计文档原定 ECharts，选型依据见 [聚合与图表验收][ac]）；
完整行虚拟化后续推进。

目录：`src/` 含 `app`（启动、路由、工作台与设置容器）、`components`（共享控件）、
`features`（connections/query/settings/cluster/models）、`domain`（连接身份、查询草稿、执行快照、操作状态机）、
`services`（类型化 IPC 与开发 fixture 适配）、`locales`（zh-CN/en-US，按业务命名空间）、`styles`（语义 token、主题与排版）；
`src-tauri/` 含 `src`（connection/operation/storage/query 等模块）、`capabilities`（最小桌面权限）、`migrations`（版本化 SQLite 迁移）；
`tests/` 含原型 `platform.test.cjs`、`unit`、`fixtures`（无真实密钥的样本、故障响应与前后端共用合同）与 `browser` 探测页；
`docs/` 保留设计与独立原型入口，`scripts/` 放原型构建与工程工具。规划的 `tests/integration/`（Rust/IPC/ES/模型协议）
与 `tests/e2e/` 尚未建立：Rust 测试在模块内，真实服务用例默认忽略。

迁移规则：

- 复用原型的布局、token、双语文案、样本和验收场景，不复制其全局 DOM 脚本作为业务架构；
  `docs/theme-preview.html` 始终可单独打开，正式应用使用独立入口。
- 原型命令保留为 `build:prototype`/`test:prototype`，与正式命令独立维护，CI 同时执行两类回归；命令变化同步 README。
- 前端只通过类型化服务访问桌面后端，不直连 ES，不引入任意 URL/认证头代理。
- 工作区状态、查询草稿、执行结果、视觉偏好分别管理；结果绑定执行快照，不绑定当前编辑器文本。
- SQLite 是正式元信息存储；密钥只进入系统密钥库或受控的会话内存。首屏外观如需缓存，
  仅保存经过校验的非敏感偏好，并明确与 SQLite 的同步规则。
- 大整数与高精度 JSON 在网络、Rust、IPC、前端、复制和导出链路无损验证，不等表格上线后再修复 `JSON.parse` 舍入。

## 7. 测试与安全关卡

| 层级 | 首批必须覆盖 |
| --- | --- |
| 领域单测 | ID 与名称分离、选择回退、连接隔离、不可变执行快照、取消/旧响应状态 |
| 查询单测 | bool/NOT/nested、缺失值、`minimum_should_match`、时间冻结、无损数值与受限转换 |
| UI 回归 | 查询默认首页、设置右侧管理、状态保留、16 组合、空/加载/失败/无权限、键盘与焦点 |
| Rust/IPC | 参数拒绝、秘密脱敏、最小权限、认证不跨主机重定向、只读白名单、存储失败 |
| ES 集成 | 精确版本、最小权限用户、401/403/429、CA 错误、无 monitor、PIT 过期、失败分片 |
| AI 集成 | 协议流解析、取消、无授权数据不出站、候选版本冲突、跨提供方再授权 |
| 发布 | 各平台安装/升级、系统密钥库、中文输入法、缩放、离线资源和支持矩阵 |

故障 fixture 必须包括超大整数、nested、多索引字段冲突、无 `_source`、乱序响应、超时、损坏配置、写入结果未知。
fixture 测试与真服务集成结果分开记录；真实测试只面向专用测试集群及明确授权资源，不在生产集群做破坏性验证。

## 8. 执行与收口规则

2026-09-30 起先持续开发，功能完成后由用户集中执行人工清单，开发中不反复启动浏览器巡检；开发关卡是可重复的自动化测试、
类型/构建和 diff 审查，不以“看起来能通过”代替实际执行。布局、真实 WebView、系统密钥库与平台集成不因延后而默认通过，
也不阻塞不依赖其结果的开发。接续流程见 [连续开发规则](continuous-development.md)。

1. 主代理核对 diff、文件所有权和既有改动，再独立运行最小充分检查。
2. 每个小项先定向测试；每批集成后运行一次 `npm run check` 与受影响 Rust 回归，不为文案变化重复 release 打包或启动浏览器。
3. 自动化通过只关闭子项的开发工作；真实服务、人工、平台与发布状态分别保留。
4. 全部实现批次结束后由用户集中执行人工清单；发现问题单独修复并回归受影响功能。
5. 父任务完成需要其完整验收与外部资源关卡通过；不报虚构百分比，不把“已派发”记作完成。
6. 每批验收记录写日期、实现位置、命令、实测平台/版本、结果与剩余风险，区分未联调、未实测与仅 fixture，演示只说明实际能力；
   本文批次索引追加一行，同步 `AGENTS.md` 交接与 backlog，命令、架构或安全约定变化时同步协作规范与 README。

- 批次 2 的本地 schema/领域层可与批次 1 的认证网络并行；共享 storage/schema 只能有一位所有者。
