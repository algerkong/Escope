## 2. 不再反复讨论的设计基线

产品范围以 [平台设计](platform-design.md) 为准；设置交互以
[设置规范](settings-and-shortcuts.md) 的最新决策为准；视觉以
[视觉系统](competitive-and-visual-design.md) 为准。
[产品设计](product-design.md) 保留查询语义、安全和结果契约，不采用其早期只读产品上限。

1. 默认首页是查询工作台。AI 初始默认收起，用户设置的下次启动偏好可以覆盖默认值。
2. 连接、模型、集群、节点、分片和索引复用设置右侧区域，左侧设置导航固定保留。
3. 关闭设置回到原查询，保留条件、草稿、结果、视图与滚动状态。
4. 连接使用不可变 ID；名称可改，顺序稳定，启动恢复上次有效 ID，否则选第一项。
5. 零连接显示添加空状态，单连接隐藏选择器，多连接的顶部与设置选择同步。
6. 切换连接不自动查询；标签固定绑定原连接，异步响应不得污染其他连接。
7. 日夜、四种强调色、中英文、字体和密度从底座阶段纳入，不在最后补国际化。
8. 只读是默认访问模式，不是能力上限；写入能力必须等待后端授权与审核流程。
9. 正式运行无默认演示连接。fixture 仅在测试或显式开发模式使用，不能在真实请求失败时替补数据。

## 3. 工程结构与迁移方式

沿用已确定的 React + TypeScript + Vite + Tailwind 4 + Tauri 2/Rust。
组件使用可访问基础控件与 Lucide；表格、编辑器、图表分别在对应阶段引入
TanStack Table/Virtual、Monaco、ECharts，不在空壳阶段一次性加载全部依赖。
国际化使用 i18next/react-i18next；具体依赖版本由 F01 验证后写入锁文件。

```text
docs/                         设计与独立原型，保留现有入口
scripts/                      原型构建及后续工程工具
src/
  app/                        启动、路由、工作台与设置容器
  components/                 按钮、表单、对话框、菜单等共享控件
  features/                   connections、query、settings、cluster、models
  domain/                     连接身份、查询草稿、执行快照、操作状态机
  services/                   类型化 IPC 与开发 fixture 适配
  locales/                    zh-CN、en-US，按业务命名空间组织
  styles/                     原型语义 token、主题与基础排版
src-tauri/
  src/                        connection、operation、storage、query 等模块
  capabilities/               最小桌面权限
  migrations/                 版本化 SQLite 迁移
tests/
  platform.test.cjs           保留的原型测试
  unit/                      领域与组件测试
  integration/               Rust/IPC/ES/模型协议集成测试
  e2e/                       浏览器工作流测试
  fixtures/                  无真实密钥的样本与故障响应
```

迁移规则：

- 复用布局、token、双语文案、样本和验收场景，不复制原型的全局 DOM 脚本作为业务架构。
- `docs/theme-preview.html` 始终可单独打开；正式应用使用独立入口。
- 将现有命令保留为 `build:prototype`、`test:prototype`；新增正式应用命令时同步修改 README，
  CI 同时执行两类回归。这些命令现已添加，正式应用与原型入口独立维护。
- 前端只通过类型化服务访问桌面后端，不引入直连 ES 或任意 URL/认证头代理。
- 工作区状态、查询草稿、执行结果、视觉偏好分别管理。结果绑定执行快照，不绑定当前编辑器文本。
- SQLite 是正式元信息存储；密钥只进入系统密钥库或受控的会话内存。
  首屏外观如需缓存，仅保存经过校验的非敏感偏好，并明确与 SQLite 的同步规则。
- 大整数与高精度 JSON 在网络、Rust、IPC、前端、复制和导出链路做无损验证，
  不能等表格上线后再修复已被 `JSON.parse` 舍入的数据。

## 7. 测试与安全关卡

| 层级 | 首批必须覆盖 |
| --- | --- |
| 领域单测 | ID 与名称分离、选择回退、连接隔离、不可变执行快照、取消/旧响应状态 |
| 查询单测 | bool/NOT/nested、缺失值、`minimum_should_match`、时间冻结、无损数值与受限转换 |
| UI 回归 | 查询默认首页、设置右侧管理、状态保留、16 组合、空/加载/失败/无权限、键盘与焦点 |
| Rust/IPC | 参数拒绝、秘密脱敏、最小权限、认证不跨主机重定向、只读白名单、存储失败 |
| ES 集成 | 精确版本、最小权限用户、401/403/429、CA 错误、无 monitor、PIT 过期、失败分片 |
| AI 集成 | 协议流解析、取消、无授权数据不出站、候选版本冲突、跨提供方再授权 |
| 发布 | 各平台安装/升级、系统密钥库、中文输入法、缩放、离线资源和支持矩阵 |

故障 fixture 必须包括：超大整数、nested、多索引字段冲突、无 `_source`、
乱序响应、超时、损坏配置、写入结果未知。fixture 测试与真服务集成结果分开记录。
真实测试只面向专用测试集群及明确授权资源，不使用生产集群做破坏性验证。
