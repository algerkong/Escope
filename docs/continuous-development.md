## 每批流程

1. 只读 AGENTS 最新摘要、计划当前段与相关验收，核对 Git 状态；不重新盘点整个产品或重跑旧底座。
2. 选有边界的一批相邻子项，简短说明影响范围后编码。大型任务可让子代理独占文件并行，简单任务主代理直接完成；
   共享合同单一所有者，写同一 checkout 的会话不能重叠。
3. 做最小充分验证：受影响测试、对应 lint/typecheck，Rust 对应模块/fmt，UI 按需构建。
   高风险安全、IPC、schema 和写入流程不能省掉必要失败/取消/隔离用例；全量回归在高风险批次或阶段收口执行，
   原型未改不跑，不延长测试阈值掩盖错误；JSDOM 替身不当原生证据。
4. 更新 AGENTS、plan 批次索引、backlog 状态与对应 acceptance 记录（人工事项按实列入人工清单）；检查 diff 并提交本批。
   使用 main 与现有 Git 身份，不 amend 无关提交，不推送，不提交 `.claude/`、`.vscode/` 或秘密。
5. 连续模式下，待全部委派/命令退出并确认提交后，用 `list_projects` 定位 EScope，以 `create_thread` 的 project/local
   新建恰好一个后继（不建 worktree），标题以“EScope 接续”开头；提示只给当前 HEAD、下一批范围、关键约束、文档入口和本授权。
6. 以一次紧凑 `wait_threads` 确认后继已开始，输出会话引用后退出；当前会话此后不再写仓库。
   后继继承每批提交、继续开新会话和最终睡眠条件，不等待用户逐项确认。
   创建失败时保留提交并如实报告/有限重试，不伪造已开始，也不绕过授权创建外部代理。

## 接续监控

- 应用中的“EScope 连续开发接续”低频 heartbeat 仅作中断补接，不承担代码写入。
- 优先检查其记录的当前开发会话；运行中、等待审批/输入或已有活跃后继时不重复创建；
  已完成且无后继时，只在明确有可执行剩余项时创建一个 local 后继。
- 正常交接时保留既有频率/通知配置，只更新当前会话 ID；无变化保持安静，仅在中断、失败、需用户操作或最终完成时通知。
- 依赖应用与本机环境可用，不构成远端常驻服务或完成保证。

## 结束条件

- 自动化通过、待人工验收、外部阻塞和全部完成分开记录；未授权的真实 ES/密钥库、生产写操作、许可证、
  签名/跨平台环境不能当作已验证。
- 若只剩须由用户提供授权/环境/人工结果的事项，汇总具体阻塞和补验入口，不创建无意义的新会话，
  也不宣称“全部结束”或触发睡眠。
- 所有范围内任务及必需验收真正完成后：最终风险相称回归、提交全部相关成果、写最终交接，
  确认开发/测试/委派已退出并停用接续监控，然后调用系统正常睡眠；不关机、不重启、不强制结束程序，
  不改电源设置绕过失败，睡眠不可用时如实记录。
