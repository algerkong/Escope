## 范围与契约

- Enter 或发送按钮直接提交当前输入，不再弹出批准对话框；Shift+Enter 换行，IME 不误发。
  提交时立即清空已消费输入和附件，后续输入不被旧请求完成/失败/停止回调清除。
- 只有用户显式点击附加查询时，才冻结查询名称、索引与 DSL 并发送；不自动携带连接 ID、
  地址、字段、文档或查询结果。附件详情中的本地身份信息不进入 prompt。
- 同一目标可发送最多 20 条完整 user/assistant 历史消息；失败、取消、未完成的交换不进入历史。
  prompt 64 KiB、单条历史/输出 256 KiB、prompt+history 512 KiB；裁剪完整旧配对并标记范围。
  会话最多 30 个交换、12 个目标记录，均只在会话内存中保留。
- 使用已保存模型的稳定 ID。后端回读配置，核对协议、地址与模型 ID 后才请求；
  会话、草稿、附件按目标隔离，切换不转发旧内容。隐藏 AI、进入设置、删除或更改目标会停止旧请求。
- 首批协议限定为 OpenAI-compatible Chat Completions SSE 与 Ollama `/api/chat` NDJSON；
  不是 OpenAI Responses、其他原生提供方、工具调用或查询候选审核。
- 通过类型化 `ai_chat` / `ai_chat_cancel` 和单次调用的 Tauri Channel 传递文本；
  只接受受限目标校验与有界 conversation 消息，不能提供任意方法、认证头或工具代理。
- 模型网络与 ES 网络独立。持久 API Key、远程模型获取与选择已纳入本批；
  用量/费用统计、会话持久化、文档/结果授权与候选应用仍不在本子项范围。
  浏览器预览不保存密钥、不发起模型请求，也不回退到模拟响应。
- 回复使用受限 Markdown：禁 raw HTML 和远程图片自动加载，代码只显示/复制；
  失败末条可按原始 prompt/history 重试，新的输入草稿不被重试消费。
- 模型选择/刷新/设置位于底部输入区，顶部只保留会话工具；长消息、代码、表格和附件内部滚动。
  宽度/布局、预览与表格证据另见 [工作台验收](workspace-grid-and-ai-qa.md)。

本轮用户追加授权的兼容协议测试端点为 `http://127.0.0.1:8788/v1`，
模型为 `glm-5.3-flash`。无认证的模型列表探测实际返回 HTTP 401。
最初追加 A02.2 单次认证，现已接入模型设置的持久密钥：
schema v4 仅保存凭据引用，密钥存系统密钥库；前端只获得 `hasApiKey`，
不获得密钥或引用。密钥替换/清除/删除复用持久清理队列，清理失败不能冒充完整成功。
聊天默认使用保存的密钥；可选单次覆盖仍不进入模型元信息、对话、文档或日志。
用户随后明确要求充分自定义 AI，取消先前的 HTTPS/回环限制：自定义 HTTP/HTTPS 地址、
端口、基础路径与模型 ID 均允许；HTTP 保留非阻断的未加密提醒，不强制改成 HTTPS。
模型发现使用固定 `GET /models` 或 `GET /api/tags`；允许先填地址/密钥再选模型 ID，
列表不可用时保留手填。其他认证方式和原生提供方协议仍另行实施。

协议依据（前会话记录，本轮通过受控协议测试复验）：

- [OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/typescript/resources/chat/subresources/completions/methods/create)：
  `stream: true`、`choices[].delta.content`、`finish_reason` 与 `[DONE]`。
- [Ollama 官方 Chat 文档](https://docs.ollama.com/api/chat)：
  `/api/chat`、`messages`、NDJSON、`message.content` 与 `done`。
