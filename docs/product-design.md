# EScope 产品与交互设计方案

版本：0.4，设计提案  
日期：2026-09-30  
状态：用于原型与研发拆解，非已实现功能或兼容性承诺。

最新交互基线：默认查询首页、AI 默认收起；连接/模型/集群/节点/分片/索引直接显示在设置页右侧，
左侧设置导航不变。管理功能不使用独立首页或配置弹窗；详情、编辑与危险确认可使用局部对话框。
工作区按稳定 ID 恢复上次连接，否则默认第一项；单连接隐藏选择器，多连接支持右上角和设置同步选择。
名称可在连接中心配置、重命名，切换连接不自动执行查询、不复用其他连接的数据。

最新范围以 [桌面管理工作台设计](platform-design.md) 为准：新增多种连接、监控健康、节点分片、
索引与运维管理、受控 REST、多提供方与手动模型选择。本文后续的只读首版与阶段安排保留为
早期查询模块方案，不再限制整体产品范围；只读改为默认访问模式。

补充规范见 [竞品与视觉系统](competitive-and-visual-design.md)。
外观新增跟随系统、日间、夜间与四种强调色；中英文为首版必需能力。
视觉冲突以补充规范为准；前端样式确定采用 Tailwind CSS，独立样式预览见 [主题预览](theme-preview.html)。

## 1. 产品定义

EScope 是面向 Windows、macOS 和 Linux 的 Elasticsearch 桌面查询工作台。

核心价值：

1. 日常查询无需编写 DSL。
2. 复杂查询不受可视化能力限制。
3. 文档、日志和聚合结果都清晰可读。
4. AI 辅助生成与理解查询，但用户始终控制执行和数据发送。

首要用户是后端开发、测试和技术支持人员。数据分析人员是次要用户。
首版聚焦只读检索，不做集群运维、索引创建、文档修改或完整 BI 平台。
不要求注册账号，不依赖产品方云服务；不配置 AI 也能使用全部基础查询能力。

## 2. 首条闭环

示例场景为虚构订单数据，仅用于原型，不代表真实客户或产品指标。

用户需要查找最近 24 小时支付失败且金额大于 500 的订单，理解失败原因，并保存查询。

1. 创建连接并测试凭证和 TLS。
2. 选择 `orders-*`，确认时间字段 `created_at`。
3. 添加 `status` 精确匹配 `failed` 和 `amount > 500`。
4. 执行后在表格查看订单号、金额、状态和错误消息。
5. 打开一条文档，在详情中检查嵌套支付记录。
6. 向 AI 提问“按错误码统计数量”，审核生成的聚合查询后执行。
7. 将查询保存为“支付失败排查”，保留相对时间配置和展示列。

原型必须跑通整条流程，而不只展示静态首页。

## 3. 信息架构

| 一级区域 | 子区域 | 职责 |
| --- | --- | --- |
| 查询工作台 | 连接、索引、字段、查询标签、结果 | 高频工作入口 |
| 查询库 | 收藏、目录、最近运行 | 复用查询 |
| 连接管理 | 地址、认证、证书、环境标签 | 管理访问边界 |
| 模型设置 | 提供方、模型、凭证、隐私策略 | 管理 AI 接入 |
| 应用设置 | 主题、密度、时区、历史、更新 | 本地体验与维护 |

查询库和设置按需打开，不与主工作台争抢固定空间。
导出任务通过状态入口和任务面板呈现，不占用独立一级导航。

## 4. 工作台布局

采用“左侧资源导航 + 中央查询与结果 + 可收起 AI 面板”。

| 区域 | 建议尺寸 | 行为 |
| --- | --- | --- |
| 顶栏 | 高 44px | 工作区、环境、搜索、设置 |
| 左侧资源栏 | 默认 240px，范围 200–360px | 搜索连接与索引，查看字段 |
| 查询标签栏 | 高 36px | 新建、关闭、拖动排序、未保存标记 |
| 查询编辑区 | 默认约 240px | 可视化与 DSL 切换，可调整高度 |
| 结果工具栏 | 高 40px | 数量、耗时、状态、视图、导出 |
| 结果区域 | 占用剩余空间 | 表格、JSON、图表 |
| AI 面板 | 默认 360px，范围 320–480px | 候选查询、解释、对话 |

以上为原型起始值，不是未经验证的最终规范。
详情打开时，在较宽窗口内与结果并排；空间不足时使用覆盖式抽屉。
详情与 AI 不同时挤压主表格到不可用宽度。

窗口适配：

- 1440px 及以上：允许三栏同时展开。
- 1100–1439px：默认收起 AI，需要时展开并允许收起资源栏。
- 小于 1100px：右侧内容使用覆盖面板；查询工具栏按优先级收纳。
- 最小目标窗口为 1024 × 700，需验证 125%、150% 和 200% 显示缩放。
- 浏览器原型的小屏展示使用单主区域与抽屉，不把桌面三栏等比缩小。

## 5. 连接体验

连接表单包含名称、环境、服务地址、认证方式和高级 TLS 设置。
首版认证方式为无认证、用户名密码和 API Key。

流程为“填写 → 测试 → 查看能力与权限 → 保存 → 选择索引”。
测试成功不自动查询数据；索引列表权限不足不等于连接失败，允许输入已知索引名称。

错误区分 DNS、连接超时、证书不可信、认证失败、授权不足和 ES 不兼容。
优先支持自定义 CA，不把关闭证书校验作为常规路径。
生产环境始终展示文字与颜色双重标识；颜色不是唯一提示。

凭证保存在系统凭证存储，SQLite 仅保存凭证引用。
导出连接配置不包含凭证。系统密钥库不可用时使用会话内凭证并解释限制，不回退到明文保存。

## 6. 可视化查询

### 6.1 条件行

条件行由字段、操作符和值组成。选择字段后，操作符和值控件按类型变化。

| 字段类型 | 首版操作 | 值控件 |
| --- | --- | --- |
| keyword | 等于、不等于、属于集合、存在 | 输入框、多值输入 |
| text | 全文匹配、短语匹配、存在 | 文本输入 |
| integer / long / double | 等于、大于、小于、区间、存在 | 校验型数值输入 |
| date | 之前、之后、区间、最近一段时间 | 日期与相对时间控件 |
| boolean | 是、否、存在 | 分段选择 |
| object | 展开子字段 | 字段树 |
| nested | 在指定嵌套对象内配置条件组 | 显式 nested 分组 |

字段列表显示类型、可搜索性和可聚合性。
不假设每个 text 字段都有 `.keyword`，必须依据实际 Mapping。
多索引类型冲突时明确展示受影响索引，要求缩小范围或进入 DSL。

### 6.2 布尔语义

支持 AND、OR、NOT 和条件组，默认 AND。
OR 组编译时明确设置 `minimum_should_match`，不能依赖 bool 上下文默认值。
精确与范围条件默认进入 filter，上下文需要评分的全文条件进入 must。

“不等于”明确区分“排除匹配值，包含缺失字段”和“字段存在且值不等于”。
条件显示中的自然语言必须反映这一差异。
同一 nested 分组内条件必须落到同一嵌套对象，不按普通对象路径生成过滤。
Q02 显式 nested 首批限顶级 nested 路径及直接标量字段，Mapping 原文与 field caps
报告的实际索引集合须一致。内部否定仍可能被其他对象满足；“不存在匹配对象”的父文档
排除使用外层 `must_not`，且不越出所属 OR 分支。每组 `score_mode: none`、
`ignore_unmapped: false`；完整预览后显式应用，不执行、不反向改写手写 nested。
限制与未验语义见 [nested QA](query-nested-filters-qa.md)。

待应用筛选的逐条启停保留定义、精确值和组归属，禁用仍占条件/组配额；
组内没有启用成员时不参与任何组合，包括 OR 与 nested 父文档排除，不生成空查询。
全部禁用只预览未改动的原 DSL/时间绑定，不提交空操作，列表未结束前仍保护运行/保存。
上述空操作限制针对尚未应用的列表。启停需重新预览，重新启用需当前字段证据。
第七批应用后保留会话定义和禁用项，替代第六批的混合应用弃用确认；已应用定义与待应用
编辑副本独立，关闭未改动审核不产生待应用操作，取消编辑不改已应用定义。

会话绑定显式持有深冻结的基线文档、已应用文档、定义/分组和观察快照；后续审核从基线
重新生成完整 DSL，不重复追加 wrapper。全禁用可恢复精确基线并保留定义，移除最后一项
须预览后提交，零项编辑仍保护运行/保存。只移除本次绑定的条件，不识别或改写相似手写条件。
手改 DSL/目标、时间、排序、参数、视图定义或其他修订导致失配时，拒绝覆盖新草稿；
明确解除绑定只遗忘会话定义，当前 DSL 和结果保持原样。
新执行的时间冻结、旧 PIT/历史与绑定副本独立；索引入口仅明确生成同目标新查询，保留
原始观察身份，不伪造新查询已经执行。绑定不进 IPC/持久化，反序列化形状不恢复托管，
重启仅恢复已应用 DSL。会话证据见 [会话绑定 QA](query-filter-session-qa.md)；
[启停 QA](query-filter-enablement-qa.md) 保留第六批历史证据。

第八批固定库 v1 接平面 mapped，第九批 v2 增加显式顶级 mapped nested/直接标量字段，
第十批 v3 增加平面查询期 runtimeMapping。保留路径、同对象组与父文档匹配；
同组重复拒绝，独立对象组可重复条件。v1/v2 读取不改写，显式新增升级为 v3，
删除保持原库版本，已存版本不降级。显式命名、全文核对字面量后保存；
保留原 token、布尔关系和启停，不保存端点、结果正文、执行/PIT、DSL、会话基线或绑定。
runtime 声明只从当前已应用 DSL 提取；精确类型/源码/可选语言形状分别保留，
同字段条件不得使用不同声明或混用 mapped/runtime。现场值须核对真实观察，保存字面量
不伪装成执行 fields；禁用项保存也须核对当前声明。全文脚本文字另行显式确认。
仅七类型/同名 source 或受限内联 Painless；date/IP/geo_point runtime 仅存在性；
nested runtime 及任意深层路径仍拒绝，不静默裁剪。单脚本 4 KiB，去重声明集合 32 项/64 KiB。
库最多 100 组/256 KiB，每组 32 条/8 个非空组、值 4 KiB，既有定义 ID 不覆盖或换目标；
schema v8 独立 SQLite 行串行 CAS，新 ID 同事务检查连接存在，损坏/未知版本/冲突不覆盖。
同连接 ID + 完全相同目标才可加载为待审副本，不覆盖已有待应用/已绑定筛选。
保存字面量不是当前执行原值，无执行观察时为 null；启用 mapped 项须当前字段证据，
runtime 遮蔽拒绝；启用 runtime 项须匹配当前 DSL 的精确声明，不从旧执行或视图库推断，
不插入/替换/运行脚本。首次加载启用的 nested 项须打开审核后重新获取 Mapping/field caps，
实际索引集合非空且一致、顶级路径/直接字段/类型须匹配，不用打开前缓存或保存时证据。
禁用只跳过当前证据，不跳过结构、成员、值或配额；启用后重新审核。
完整最终 DSL 审核后显式应用，不自动执行；库删除不改已加载副本。
索引仅生成同目标新查询，随后真实新观察保留其实际身份，不从恢复数据重新信任会话绑定。
锁定索引 DSL 缺少查询期声明时，加载后预览拒绝，不生成新查询或改写原索引标签。
证据与未验范围见 [固定 runtime QA](pinned-runtime-filters-qa.md)，
v1/v2 证据保留于 [固定筛选 QA](pinned-filters-qa.md) 和 [固定 nested QA](pinned-nested-filters-qa.md)。

### 6.3 时间与聚合

时间范围显示选用字段和时区，执行时冻结相对时间为绝对边界。
界面时间条件不向任意 DSL 悄悄注入过滤。Q02 首批提供显式完整 DSL 审核/应用入口，
只有经过绑定校验的外层时间 wrapper 会在明确执行时重新冻结；原查询子树原文保留。
手改 DSL 或目标解除托管、保留当时绝对字面量；手写同字段范围不被覆盖。
收藏保留相对时间意图，每次执行重新解析，历史记录保留本次实际边界。
历史恢复只还原本次绝对 DSL，不重新启用相对范围。相对天为 24 小时持续时间，
绝对时间使用明确 UTC/IANA/固定偏移，拒绝不存在/歧义本地时间；date 不舍入纳秒。
本批支持/限额和未验范围见 [时间范围 QA](query-time-range-qa.md)，不据此宣称完整 Q02 完成。

基础聚合通过“分组 + 指标”完成，支持 terms、date_histogram、count、sum、avg。
高级管道聚合通过 DSL 使用；不能支持的类型仍可查看原始响应与通用聚合树。

## 7. 可视化、DSL 与 AI 的状态契约

每个标签只有一个可执行草稿，但可保留模式切换前的恢复点。

| 操作 | 处理方式 |
| --- | --- |
| 可视化切到 DSL | 从结构化查询生成 DSL，保存可视化恢复点 |
| 修改 DSL 后切回可视化 | 仅在完整支持且语义无损时转换 |
| DSL 包含不支持语法 | 保持 DSL；可复制新标签继续，不覆盖源码 |
| 恢复之前的可视化版本 | 展示将丢弃的编辑差异，明确确认 |
| AI 生成查询 | 先作为候选，不直接覆盖草稿 |
| 应用 AI 候选 | 比较基础草稿版本；有新编辑则要求重新确认 |

DSL 原文、格式与未识别字段必须保留；不能为了统一模型而删去高级能力。
DSL 模式首版编辑 `_search` 请求体，索引与连接仍由明确的上下文选择器控制。
任意端点、多请求控制台不是首版能力。

每次执行生成不可变快照，包含连接引用、索引范围、DSL、实际时间边界、分页参数和执行编号。
结果绑定执行快照而非当前编辑器内容。编辑后旧结果显示“查询已修改，结果来自上次执行”。
旧请求晚于新请求返回时不能覆盖新结果；取消后到达的响应也不能恢复为成功状态。

## 8. 数据展示规范

### 8.1 表格

- 支持行列虚拟化、列宽调整、固定列、列选择、排序和复制。
- 初次展示优先选择用户时间字段及少量标量字段，不默认展开全部 Mapping。
- 对象与数组显示类型和摘要，点击展开；不把嵌套数组强制拆成多行。
- 缺失、null、空字符串和空数组使用不同显示形式。
- 单元格操作可将值追加到过滤器；该操作修改草稿，不自动执行。
- 排序切换重置分页并重新查询，不只排序当前已加载的一页。

### 8.2 文档详情

提供结构化字段视图与原始 JSON，支持字段搜索、路径复制、值复制和折叠。
保留 `_index`、`_id`、`_score` 等元数据，不与 `_source` 的同名字段混淆。
缺少 `_source` 或仅请求 fields 时解释数据来源，不把文档显示成没有数据。
高亮片段按文本片段安全渲染，不把服务端或文档内容直接当作 HTML 插入。

### 8.3 精度与图表

长整数与高精度数值在 Rust、IPC 和前端全链路采用无损表示。
复制和导出优先保留原始数值文本；绘图确需浮点转换时检查范围和精度，并给出限制提示。
“复制格式化显示值”与“复制原始值”使用不同命令。

图表仅绑定可识别聚合或明确的本地样本统计。
图例和标题标注索引、时间范围、指标和数据范围。
Top N 不是全量分类分布；terms 误差、cardinality 近似值、未返回桶均需适当标识。
点击图表只提出追加条件，不意外触发重复重查询。

## 9. 分页、性能与导出

文档浏览采用 PIT + search_after，使用稳定排序与唯一决胜字段。
使用响应最新返回的 PIT 标识，记录页游标；只支持顺序前进与已访问页回退，不承诺任意跳到第 N 页。
PIT 过期提示重新执行，不静默换快照拼接数据；关闭标签或查询替换时释放资源。
不支持 PIT 或权限不足时，明确降级到受窗口限制的分页，不伪装稳定快照。

命中数区分精确值和下界，不把 `gte` 显示成准确总数。
展示 ES took 与客户端总耗时，区分服务端执行、网络传输和展示成本。
超时、失败分片和部分结果作为执行状态展示，不能只显示绿色成功。
停止请求不等于确认 ES 服务端任务已停止；界面不作超出能力的承诺。

导出区分当前页、已加载记录和完整查询结果，完整导出需要确认规模和目标路径。
使用独立且与执行快照绑定的分页任务，流式写入，支持进度、取消和磁盘错误反馈。
输出 CSV 和 JSONL；CSV 防范公式注入，嵌套值编码为 JSON，明确数值与日期导出规则。
取消或失败保留显式标记的部分文件，不将其冒充完整成功文件。
原始响应与解码缓存设上限；不能同时无限保留全量原文、对象树和表格行。

2026-10-09 的 Q07 第三批已实现该全量子项的开发闭环，见 [导出 QA](snapshot-export-qa.md)：
CSV 为固定 `_index,_id,_source,fields` 文档列，JSONL 保留完整 hit；与已加载导出的展开字段列区分。
每批最多 1,000 行、响应最多 1 MiB；单任务最多 1,000,000 行/1 GiB，30 分钟扫描预算。
只有有效空页和成功刷盘/替换才构成完整文件；限额、部分分片、失败、未知清理分别报告。
动态时间/脚本/函数评分/外部文档引用、聚合与不支持的分页/排序格式不静默转换。
实际原生磁盘、真实版本/权限、性能与跨平台验证仍待补；参数与配置交换由随后第四批独立交付。

### 9.1 参数与本地查询定义交换

2026-10-09 Q07 第四批开发自动化通过，证据见 [参数与交换 QA](query-parameters-and-exchange-qa.md)。
参数定义为独立版本化模板与名称/类型列表，整值占位 `{"$param":"name"}` 不插值键名、
字符串片段、连接或索引；支持六种 JSON 类型，数值和嵌套 JSON 的 token 不经浮点重写。
最多 32 参数/1,000 占位，单值 64 KiB，模板和最终 DSL 256 KiB，深度/节点也有界。

保存定义不改当前可执行 DSL；预览后显式应用才改草稿，必须仍匹配原 ID/连接/索引/修订和正文。
两者均不执行，原有结果仍绑定旧快照。未完成模板可以本地保存，但不能预览/交换或直接执行。
输入值不作为参数状态持久化；应用后的最终 DSL 仍按既有草稿/历史规则保存。
schema v6、查询库/恢复文档 v1 保持，可选参数子对象自带 v1；旧文档可读，未知子版本拒绝。

本地交换格式为 `escope-query-definitions` v1，只包含用户选择并审核的查询定义/参数模板和
来源标签，最多 100 项/4 MiB；不含实际连接 ID/端点、认证/引用/CA、历史、结果、模型或偏好。
这不是完整配置备份、团队共享或 Kibana Saved Objects 兼容格式。
白名单与已知敏感键/认证值检查不能自动识别所有无标签敏感字面量，导出仍需用户审核。

导入要求每个来源逐项映射本地稳定 ID + 端点，或明确保持未绑定；名称只作提示。
映射目标在写事务内再次检查，全部新条目以新 ID 一次追加，不覆盖同名条目，不开标签/执行。
普通保存和导入均比较已读完整库；损坏/未知版本/冲突不修复覆盖，未知完成后重试不能重复新增。
原生选择路径，完整刷盘后原子替换；浏览器为 session/下载请求，实际磁盘和桌面行为另验。

## 10. AI 交互与安全

### 10.1 接入

首版接入 OpenAI-compatible 协议与 Ollama。
统一适配生成、流式输出、取消、能力声明和错误分类；不假设所有兼容服务支持相同结构化输出能力。
模型密钥由后端使用，不暴露到前端持久化、错误日志或导出配置。
默认不启动任何模型调用，测试连接也需由用户触发。

### 10.2 默认权限

| 数据或操作 | 默认策略 |
| --- | --- |
| 用户问题 | 点击发送后传给选定模型 |
| 相关字段结构 | 首次或策略变化时披露范围，经确认发送 |
| 原始文档、字段样本、聚合结果 | 默认不发送，按本次目的选择并确认 |
| 凭证、连接认证头 | 永不进入模型上下文 |
| 查询执行 | 生成后由用户审核并执行 |
| 写入与管理端点 | 不开放给 AI |

本地模型不自动等于安全可信；自定义提供方明确展示实际地址。
隐私设置可按连接配置，生产连接默认更严格；用户可清除本地对话记录。

### 10.3 查询生成

处理流程为用户意图、相关字段筛选、候选生成、语法与字段校验、风险检查、展示差异、用户执行。
含糊问题要求确认时间范围或业务字段，不凭空创造业务含义。
昂贵查询采用规则提示：超大 size、宽范围、前导通配符、脚本和高桶数聚合等。
成本提示是启发式，不承诺能准确预测 ES 执行成本；后端仍设置超时和资源边界。

### 10.4 结果解释

总结明确区分观测事实、推断和待验证假设，并关联执行编号。
当前页数据只能解释当前页；统计总体趋势优先提出聚合查询，不拿分页样本代表总体。
模型可以建议图表，但只返回通过 schema 校验的图表描述，不能执行任意代码或加载外部资源。
结果文档和工具输出都视为不可信数据，不允许其改变工具权限或系统指令。
模型故障不影响普通查询，保留候选和错误信息供重试。

## 11. 视觉与可用性

风格为紧凑、克制的专业工作台。主要内容是数据，不是装饰性面板。

| --- | --- | --- |
| 背景 | #F5F6F7 | #17191B |
| 主表面 | #FFFFFF | #202326 |
| 边框 | #DDE1E5 | #373C41 |
| 主文字 | #202428 | #E8EBED |

| 主操作 | #087F72 | #48C9B0 |

这些是待对比度测试的初始配色，不能替代 WCAG 验证。
中文使用系统字体，拉丁字符建议 IBM Plex Sans，代码使用 JetBrains Mono。
正文 13–14px，紧凑表格行高约 32px、舒适模式约 40px，字距为 0。
常规控件圆角 4px，弹窗 6px；区域通过分割线组织，不使用层层嵌套卡片。

## 12. 技术架构

推荐 Tauri 2 + React + TypeScript + Rust，作为原型验证后的首选方向。
选择理由是本地访问边界清晰、跨平台打包和较轻桌面壳；代价是 Rust 开发与多 WebView 验证成本。
如果团队完全没有 Rust 经验，应在技术验证阶段与 Electron 做同功能样例比较，再锁定。

| 层 | 建议组件 | 边界 |
| --- | --- | --- |
| UI | React、可访问基础组件、Lucide | 交互与展示，不直接管理凭证 |
| 表格与编辑 | TanStack Table/Virtual、Monaco | 展示能力，不承担 ES 语义 |
| 图表 | ECharts | 消费受校验的数据与配置 |
| 查询领域层 | 类型化查询模型、编译器、受限反向解析 | 可视化与 DSL 语义 |
| 桌面后端 | Rust HTTP/TLS、执行管理、文件流 | 网络、权限、分页、取消 |
| 本地存储 | SQLite + 系统凭证存储 | 元信息和密钥分离 |
| AI 适配 | 提供方接口与安全策略 | 模型调用与数据范围控制 |

前后端命令应包括连接测试、索引发现、字段读取、执行查询、加载下一页、取消和导出。
不提供允许前端自由指定任意地址、方法和认证信息的通用代理命令。
读取型能力通过端点与方法白名单定义；例如 PIT 的创建与释放并非 GET，但属于受控读取生命周期。
后端验证连接归属、索引范围与命令参数；客户端只读约束不能替代 ES 服务端最小权限账号。
网络重定向不得将认证信息转发到未经授权的主机。

## 13. 核心数据对象

| 对象 | 必需信息 |
| --- | --- |
| ConnectionProfile | 标识、地址、环境、TLS、凭证引用、能力缓存 |
| QueryDocument | 标识、连接引用、索引范围、模式、草稿、版本、展示配置 |
| WorkspaceState | 当前连接 ID、每连接查询上下文、当前视图；与连接显示名称分离 |
| VisualQuery | 条件树、nested 作用域、排序、返回字段、时间、聚合 |
| ExecutionSnapshot | 查询版本、实际请求、时间边界、开始时间、执行编号 |
| ResultSession | 执行编号、PIT、页游标、总数关系、状态、有限缓存 |
| SavedQuery | 查询内容、参数意图、列配置、名称、标签 |
| AIProposal | 基础草稿版本、候选 DSL、解释、风险、发送范围 |
| ExportJob | 执行快照、输出路径、格式、进度、完成或中断状态 |

本地历史可能含敏感查询值，应支持禁用、保留期限与一键清理。
默认不持久化结果内容；恢复标签只恢复草稿，不自动重新访问生产集群。
删除连接时解释受影响的收藏，保留可重新绑定的查询内容。

## 14. 跨平台与版本策略

目标覆盖 Windows、macOS、Linux，但发布支持必须以实测矩阵为准。
原型优先在当前 Windows 环境开发；macOS 和 Linux 不能通过 Windows 测试推断成功。

验证 WebView、Monaco 输入法、字体、缩放、证书链、代理、系统密钥库和文件路径。
安装与升级覆盖代码签名、macOS 公证、签名更新和本地数据库迁移。
Linux 先明确发行版、桌面环境和安装包格式，不笼统宣称所有 Linux 可用。

ES 首先验证 8.x 的具体小版本，再补充 7.17 与 9.x。
能力以实际探测和集成测试为准，版本字符串仅作为辅助；OpenSearch 单独建兼容矩阵。
首版暂缓 SSH 隧道、复杂代理、SAML/OIDC 交互登录和云厂商签名认证。
这些能力需依据目标用户真实连接环境重新排序。

## 15. 研发阶段与验收

### 阶段 A：交互与技术验证

交付连接表单、可视化查询、DSL、表格、文档详情和 AI 候选面板的可交互原型。
模拟数据必须标识为演示数据，模型和连接不得伪装真实成功。
并行验证 Tauri 中的编辑器、长整数传输、大 JSON 渲染和系统凭证存储。

验收：首条闭环无断点；空、加载、成功、失败、取消状态均可演示；窄窗口与高缩放无关键遮挡。

### 阶段 B：查询基础

交付真实连接、字段发现、条件编译、DSL 执行、结果、稳定分页、历史、收藏和 CSV/JSONL 导出。

验收：选定 ES 版本下的集成测试通过；查询切换不丢条件；无损数值链路成立；
分页无重复或跳漏；PIT 过期明确提示；取消与新旧请求竞态不串结果。

### 阶段 C：包含 AI 的首个完整产品版本

交付模型配置、候选生成、差异审核、查询解释、基础聚合图表和受控结果总结。
阶段 B 是内部基础版，不能替代用户所要求的包含 AI 的完整首版。

验收：模型未获授权不能读取文档；候选不自动执行；不存在的字段被指出；
样本解释不冒充总体结论；生产凭证不进入模型请求或日志；AI 故障不阻塞普通查询。

### 阶段 D：桌面发布与增强

完成三平台安装和升级验证，补齐兼容矩阵、性能基准、文档对比和高级聚合。
查询性能分析、更多认证方式和共享能力依据反馈排序。

验收：分别记录三个平台的测试结果，不以“可编译”替代完整可用性验证。

## 16. 测试与基准

- 单元测试：布尔组、缺失值语义、nested、时间冻结、数值无损、支持子集反向转换。
- 集成测试：真实 ES 权限边界、多索引冲突、PIT 生命周期、聚合、部分失败与导出。
- 交互测试：模式切换、AI 候选过期、关闭未保存标签、断网恢复、结果与编辑状态分离。
- 安全测试：恶意文档、HTML 高亮注入、CSV 公式、模型提示注入、认证重定向。
- 展示数据集：宽表、长日志、深层 JSON、大数组、超大整数、缺失 source 和混合 Mapping。
- 性能基准：固定设备、数据集、网络和 ES 版本，记录首次渲染、滚动、内存和导出吞吐。

性能验收阈值在技术样例实测后制定，当前不凭空承诺百万行流畅或固定查询延迟。
